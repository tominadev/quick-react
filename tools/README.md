# tools —— 装在别的机器上的工具

跑在平台运维或接入方机器上、调平台接口的程序。按站点分目录，与 `server/routes/<site>/`、
`docs/sites/<site>/` 同名：

| 工具 | 干什么 | 装在哪 |
| --- | --- | --- |
| [sms/shortcut-generator](sms/shortcut-generator/) | 批量生成并签名 `.shortcut`，登记为可领取令牌 | 平台侧一台已登录 iCloud 的 Mac |

和 `scripts/` 的区别：`scripts/` 是这个仓库自己的开发期脚本（类型检查、测试、迁移），跑在开发者
机器上；`tools/` 是交付出去、长期在别人机器上运行的产物。

## 每个工具都要守的

- **自带 README**：干什么、装在哪台机器、怎么构建、怎么跑、有哪些已知缺口。
- **配置走 `.env.example`**，真 `.env` 不进版本库，权限 600。
- **没有配置也要能构建。** 干净检出的仓库必须编得过，否则没人能验证改动——缺配置是运行时才报错的事。
- **认证默认用 Ed25519 密钥对**：密钥对在那台机器上生成，平台只登记公钥（AGENTS.md「平台是可信公钥登记处」）。要用平台铸造的口令，必须在 README 里写明**这一端为什么做不到密钥对**，并列进「已知缺口」。
- **构建产物一律 gitignore**：二进制、`.app`、`.zip`、生成的源码（`Embedded.swift`）、运行状态文件。
- **接口契约写在 `docs/sites/<site>/`**，工具的 README 只讲操作，不复述协议——两处都写就会有一处先过期。
