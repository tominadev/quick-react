# SMS Mac Shortcut 生成器需求开发文档

状态：需求已确认，未实施。

配套文档：[SMS 站点与 Ed25519 设备绑定](sms-site-and-ed25519-binding.md) 定义站点、数据模型与绑定协议。本文只定义 Mac 生成器的行为；令牌领取、账号绑定、手机管理和对象下载都在那一份。两份文档共用绑定文档 §4 的数据模型与 §11 的无事务约束。

## 0. 词汇约定

与绑定文档 §0 一致：**手机 → SMS 叫"接收"**（接收接口 `/api/shortcut/message-receive`），**SMS → 用户服务端叫"推送"**（`sms_push_endpoints`，不在本工具范围）。本工具只关心前者，因为接收地址要写进每个 Shortcut。

## 1. 背景

手机侧由 iOS Shortcut 收到短信后调用 SMS 接收 API，认证方式是每台设备独有的 Bearer 令牌。这些 Shortcut 由平台预先批量生成，进入公共池，用户绑定手机时领取一个。

`.shortcut` 文件的生成与签名依赖 macOS 本机工具链，服务端无法代劳，因此必须有一个在平台侧 Mac 上运行的命令行工具。**这也意味着令牌只能由本工具创建，后台管理端没有创建令牌的入口**，管理端只能撤销、回收和重新分配已存在的令牌。

普通账号用户不运行这个工具，也不持有平台预配凭证。

## 2. 目标与边界

### 目标

- 批量生成带唯一令牌的 `.shortcut` 文件。
- 上传到 SMS 的私有对象存储，并在服务端登记为可领取的令牌。
- 原始令牌只存在于 Shortcut 文件与用户手机，不进入数据库、日志、清单或 API 响应。
- 中断后重新运行只补齐未完成项，不产生重复的有效令牌。

### 不在本工具范围

- 不连接 SQLite、MySQL、PostgreSQL 或 D1，不直接修改任何数据库。
- 不为账号绑定手机，不处理 Ed25519 绑定票据。
- 不读取短信、不发送短信、不管理账号。
- 不生成永久公开下载地址，不上传到公共目录。

## 3. 凭证与术语

| 名称 | 用途 | 谁持有 |
| --- | --- | --- |
| 原始令牌 | Shortcut 调用接收 API 的 Bearer 凭证 | 只在 Shortcut 文件与用户手机 |
| `token_sha256` | 原始令牌的摘要，服务端据此查找与比对 | 服务端数据库 |
| 平台预配凭证 | 本工具调用登记接口的凭证 | 平台运维，随 `.env` 下发，一台 Mac 一份 |

原始令牌与 `token_sha256` **敏感级别相同**：任一泄露都必须立即撤销该令牌。因此摘要同样不得出现在日志、状态文件、清单和非必要的 API 请求中。

平台预配凭证不属于任何账号，不下发给用户，不能调用短信接收或账号绑定接口。它与用户 Access Key、Ed25519 私钥的区别见绑定文档 §4.10。

## 4. 编码与格式规范

跨语言互操作要求全链路统一，本节与绑定文档 §10 一致：

- `token_sha256`、`file_sha256`：**小写十六进制**，64 个字符。
- 原始令牌：至少 32 字节系统安全随机值，以 Base64URL（去掉 `=`）表示后写入 Shortcut。
- 时间：Unix 秒。
- 请求与响应均为 UTF-8 JSON。

Ed25519 公钥与签名的编码见绑定文档 §7，本工具不涉及。

## 5. 运行流程

流程有严格的先后顺序，任一步跳过都会出问题：

```text
读取 .env → 拉取接收地址 → 生成令牌与文件 → prepare-upload → PUT 上传 → commit
   §5.1        §5.2            §5.3            §5.4 一       §5.4 二    §5.4 三
```

第二步不能省：接收地址要烤进每个 Shortcut 文件，必须取当前值，理由见 §5.2。

### 5.1 配置来自 `.env`

**全部连接配置来自一份 `.env`，工具不再调用配置接口，也不自行拼接任何地址。** 这份文件由 SMS 后台的生成机器管理页在创建或重置凭证时整体生成（绑定文档 §4.9），运维复制到对应的 Mac 即可。

```dotenv
# machine: mac-studio-01
SMS_API_BASE=https://sms.example.com/api/sms
SMS_PROVISIONING_KEY=<明文凭证，只展示一次>
```

| 变量 | 用途 |
| --- | --- |
| `SMS_API_BASE` | `config`、`prepare-upload`、`commit`、`abort` 的基址 |
| `SMS_PROVISIONING_KEY` | 平台预配凭证，一台 Mac 一份 |

**写进 Shortcut 的短信接收地址不在 `.env` 里**，开跑时从服务端拉取，原因见 §5.2。

要点：

- 首行的机器标识只是注释，**不是有效变量**，工具不读取也不提交。机器身份由服务端从凭证解析，见 §5.4。
- `.env` 只放平台预配凭证。**不含用户 Access Key，也不含 Ed25519 私钥**——工具不调用用户级 API，也不签发绑定票据。
- **凭证不接受命令行参数**（会进入 shell 历史和进程列表）。允许用同名环境变量覆盖 `.env`，便于 CI 注入。
- 文件权限 `600`，不进版本库，排除出 Time Machine 等备份范围。凭证泄露时在后台重置，旧 `.env` 立即失效；已生成并入库的令牌与文件不受影响。
- 缺少任一变量时工具直接失败退出，**不使用内置默认值**。
- `SMS_API_BASE` 是签发时的快照，但它过期是安全的：工具第一次调用就失败，响亮且不产生任何后果。站点更换域名后重新下发 `.env` 即可。

其余运行参数由命令行提供：生成数量、Shortcut 名称前缀，以及任务标识 `task_id`（不提供时由工具生成并写入本地状态文件，重跑同一批次必须复用，见 §5.5）。

### 5.2 拉取接收地址

**必须在生成文件之前调用，取到的值直接烤进每个 Shortcut。**

```http
GET /api/sms/shortcut-tokens?action=config
Authorization: Bearer <平台预配凭证>
```

响应至少包含短信接收接口的完整 HTTPS 地址。工具不得自行拼接——站点的 API 后缀由服务端配置决定（项目使用 `siteConfig.apiSuffix`），拼错会生成一批永远无法工作的 Shortcut。

**为什么这个值不放进 `.env`**：两个地址的过期风险不对称。`SMS_API_BASE` 过期时工具立刻收到失败，自纠且零代价；接收地址过期却是静默的——它会被烤进上百个文件，上传、入库、进入公共池、装进用户手机，直到某天真有短信进来才暴露，那时令牌已经分发出去，回收代价极高。因此恰恰是这个值不能做快照。不存储它，也就不需要任何新鲜度校验。

拉取失败时工具直接失败退出，**不得使用内置默认值，也不得回退到上次的值**。

### 5.3 生成单个令牌与文件

对每一项按顺序执行，任一步失败则该项中止，不调用登记接口：

1. 用系统安全随机源生成至少 32 字节随机值，作为原始令牌。
2. 计算原始令牌的 SHA-256，得到 `token_sha256`。
3. 生成并签名 `.shortcut` 文件，内置 §6 规定的内容。
4. 本地校验文件可用，计算文件 SHA-256 得到 `file_sha256`。
5. 把原始令牌从内存中清除。

第 5 步之后，**该文件是原始令牌的唯一副本**，在 `commit` 成功之前不得删除，见 §5.6。

### 5.4 上传与入库

服务端在 `commit` 之前不创建任何业务记录。

#### 第一步：申请上传票据

```http
POST /api/sms/shortcut-tokens?action=prepare-upload
Authorization: Bearer <平台预配凭证>
Content-Type: application/json
```

```json
{
  "idempotency_token": "<task_id>:<序号>",
  "file_sha256": "文件 SHA-256",
  "size_bytes": 12345
}
```

**请求不携带 `token_sha256`。** 该阶段不创建令牌记录也不做令牌查重，服务端没有使用它的场景；提前送出只会扩大摘要的暴露面。摘要在 `commit` 时才提交。

响应返回短期上传票据、服务端生成的对象键和预签名 PUT 地址，不返回原始令牌，也不返回 `token_sha256`。

对象键形如 `shortcuts/<机器 name>/<yyyymmdd>/<毫秒时间戳>-<随机后缀>.shortcut`，按生成机器分目录。两个要点：

- **机器目录由服务端从凭证解析，工具不提交任何机器标识。** 工具自称的标识可被伪造，无法作为"哪台电脑生成"的审计依据。
- **随机后缀由服务端附加，不可省略。** 本地签名耗时长并不能让 `prepare-upload` 请求错开，多个队列的请求完全可能落在同一毫秒；对象键相同会导致后一次 PUT 覆盖前一个对象，最终令牌记录指向装着另一个令牌的文件。

工具不得反推或自行拼接对象键。

**该阶段服务端完全无状态**：上传票据是自包含的签名结构（对象键、`file_sha256`、`size_bytes`、`idempotency_token`、过期时间经服务端密钥签名），不落库，也不需要过期清理任务。幂等性不靠这一步，而由 `commit` 阶段数据库上的唯一约束保证。

#### 第二步：上传文件

使用预签名 PUT 地址把 `.shortcut` 文件直接传入私有对象存储。

#### 第三步：提交入库

```http
POST /api/sms/shortcut-tokens?action=commit
Authorization: Bearer <平台预配凭证>
Content-Type: application/json
```

```json
{
  "idempotency_token": "<task_id>:<序号>",
  "upload_ticket": "prepare-upload 返回的票据",
  "token_sha256": "原始令牌的 SHA-256",
  "file_sha256": "文件 SHA-256",
  "size_bytes": 12345
}
```

`content_type` 不由工具提交，由服务端固定写入。

服务端验签上传票据、校验对象存在与摘要一致后，按绑定文档 §5.1 的四步收敛写入令牌与文件元数据。**该过程不使用数据库事务**（原因见绑定文档 §11）。对本工具而言只需知道三件事：

- `commit` 返回成功 = 令牌已是 `available`，可被用户领取。
- `commit` 返回失败 = 令牌未生效，重试同一 `idempotency_token` 会收敛到同一结果。
- 中断在中途 = 令牌停在 `pending`，不可被领取，重试可推进完成。

#### 放弃上传

上传失败或不再提交时调用 `action=abort` 释放临时对象。未被 `abort` 的临时对象由对象存储生命周期规则兜底清理。

### 5.5 幂等与断点续传

`idempotency_token` 的形式固定为 `<task_id>:<序号>`。`task_id` **由工具本地生成**，不来自服务端，首次运行时写入状态文件；序号是该批次内的 1..N 序数。

它**必须跨进程运行保持稳定**：若每次运行都生成新的 key，重跑就会创建重复令牌，与 §9 的验收条目直接冲突。因此 `task_id` 必须持久化。

`idempotency_token` 与 `token_sha256` **刻意不关联**，原因有两条，都是本文档已定的约束：`prepare-upload` 不带摘要（§5.4），状态文件不得记录摘要（下方）。key 若由令牌派生，两条同时破功。

本地状态文件记录每一项的：

| 字段 | 说明 |
| --- | --- |
| `idempotency_token` | 续传的唯一依据 |
| 阶段 | `generated` / `uploaded` / `committed` / `aborted` |
| 本地文件路径 | 用于续传时重新上传 |
| `token_id` | `commit` 成功后由服务端返回 |

**状态文件禁止记录原始令牌与 `token_sha256`。** 重跑时按阶段决定动作：`generated` 重新走 prepare 与上传；`uploaded` 直接 commit；`committed` 跳过。

服务端对同一 `idempotency_token` 的重复 `commit` 必须返回与首次相同的结果，而不是创建第二条令牌。另有两条规则：

- **同一 `idempotency_token` 的 `commit` 若携带与首次不同的 `token_sha256` 或 `file_sha256`，必须拒绝**，不得覆盖也不得返回成功。否则对象里装的是令牌 A、数据库记的是令牌 B，那个 Shortcut 永远认证不了。
- **本地文件丢失且尚未 `commit` 的项，作废该 `idempotency_token`，用新序号重做。** 原始令牌只存在于该文件，文件没了这一项无法完成；沿用旧 key 重试会撞上前一条规则。

### 5.6 本地文件的保留与删除

- `commit` 成功后删除本地 `.shortcut` 临时文件；显式传入 `--keep-local` 时保留。
- **`commit` 成功之前一律不得删除**：原始令牌此时只存在于该文件，删除等于令牌永久丢失，只能作废重生成。
- 状态为 `aborted` 的项可以连同文件一起丢弃，其令牌从未登记。

### 5.7 三处名称不可混用

| 场景 | 命名 | 由谁决定 |
| --- | --- | --- |
| 本地临时文件 | 任意，建议用 `idempotency_token` | 工具 |
| 对象存储的对象键 | `shortcuts/<机器 name>/<yyyymmdd>/<毫秒时间戳>-<随机后缀>.shortcut` | 服务端在 prepare 阶段生成 |
| 用户下载时的呈现名 | `sms-<token_id>.shortcut` | 服务端下载接口的 `Content-Disposition` |

`token_id` 在 `commit` 之后才存在，因此**不能用作本地文件名，也不能用作对象键**。

## 6. Shortcut 文件内容

每个 `.shortcut` 只内置三项：

- 短信接收 API 的完整 HTTPS 地址，来自 §5.2 的拉取结果。
- 对应的原始令牌，内部变量名为 `token`。
- 面向用户显示的手机名称或编号。

请求格式固定：

```http
POST <接收 API 地址>
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "content": "短信正文",
  "recipients": ["+8613800000000"],
  "sender": "+8613900000000"
}
```

原始令牌只放在 `Authorization` 头，不得进入 URL 或 JSON 正文。

Shortcut 不得包含平台预配凭证、用户 Access Key、Ed25519 私钥、数据库地址或管理 API 地址。

## 7. 失败处理

- 已经是 `available` 或 `bound` 的令牌不能被重置或覆盖。
- `commit` 校验失败时不写入任何业务记录，工具将该项标为可重试。
- 网络超时后重试同一 `idempotency_token`，不得改用新 key；令牌或文件已重新生成时例外，此时必须换用新序号。
- 停留在 `pending` 状态的令牌不可被领取，可由服务端定期清理或由重试推进到 `available`。
- 工具提供 `--check`：校验 `.env` 变量完整、服务端可达、凭证有效，并能成功拉取接收地址，不打印凭证或令牌。

## 8. 输出与日志

成功时输出生成数量、各项的 `token_id`、下载呈现名与最终状态，以及本次识别到的机器 name（服务端在响应中回显，便于运维确认跑在哪台机器上）。

日志可记录 HTTP 状态码与错误码。**禁止记录**：

- 原始令牌与 `token_sha256`
- 平台预配凭证与用户 Access Key
- 短信正文与完整手机号

导出清单同样禁止包含上述内容。

## 9. 验收标准

- 生成 N 个令牌后，服务端有 N 个唯一的 `available` 令牌和 N 条可下载的文件元数据，一一对应。
- 每个 Shortcut 都能用自己的原始令牌成功提交短信，服务端通过 SHA-256 比对认证成功。
- 改动令牌、把令牌放进 URL 或 JSON 正文时，接收 API 一律拒绝。
- 在 `prepare-upload` 与 `commit` 之间中断，重新运行后该项被补齐，服务端令牌总数仍为 N。
- 上传成功但 `commit` 中途失败时，令牌停留在 `pending` 且不可被领取；重试同一 `idempotency_token` 后收敛为 `available`，总数不变。
- 用同一 `idempotency_token` 提交不同的 `token_sha256` 或 `file_sha256` 时被拒绝，已有记录不被修改。
- 完整重跑同一 `task_id`，不产生任何重复令牌。
- 放弃的项调用 `abort` 后临时对象可清理，服务端没有该 `idempotency_token` 的令牌记录。
- 10 个队列并发生成时，所有对象键互不相同，没有对象被覆盖。
- 在两台不同的 Mac 上分别生成，对象键落在各自的机器目录下，`sms_shortcut_artifacts.generator_machine_id` 与实际机器一致。
- 机器在后台被停用后，该机器的凭证立即被拒绝，其他机器不受影响。
- 工具伪造或篡改机器标识不产生任何效果：该字段不参与请求。
- `.env` 缺少任一变量时工具失败退出，不生成任何文件。
- `.env` 缺变量或 `SMS_API_BASE` 过期时，`--check` 失败且不生成任何文件。
- 拉取接收地址失败时工具退出，不生成任何文件，服务端没有新增记录。
- 服务端改动接收地址后，无需重新下发 `.env`，下一次生成即使用新地址。
- 任何日志、状态文件与导出清单都不包含原始令牌、`token_sha256` 或平台预配凭证。
- `commit` 成功后本地临时文件被删除；`--keep-local` 时保留。
