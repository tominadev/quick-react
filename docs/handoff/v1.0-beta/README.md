# v1.0 beta 发布交接

本目录是 v1.0 beta 发布前的交接资料。它不是新的业务需求入口，而是把数据库命名冻结、结构审计、发布阻断项和后续执行顺序集中记录，供后续开发人员在同一套判断标准下继续工作。

## 当前结论

截至 2026-09-06，项目已经完成四套 Prisma Schema 的只读盘点，但还没有达到“可以冻结数据库结构并发布 beta”的条件。审计没有修改 Schema、迁移或业务代码；目录中的结论用于指导下一轮结构收敛。

| 项目 | 当前结果 | 发布判断 |
| --- | --- | --- |
| Prisma Schema | `base` 17 张、`global` 12 张、`passport` 31 张、`pve` 5 张，共 65 个模型 | 需要先完成公共字段顺序和命名冻结 |
| 迁移覆盖 | SQLite、MySQL、PostgreSQL、D1 均有迁移目录；编号需继续保持四种方言一致 | 可继续增量生成，禁止手写结构迁移 |
| Schema 快照 | `PRISMA_VERIFY_FORCE=1 npm run schema:verify` 已通过 | 仅表示快照已追上当前 Schema，不表示命名已经合格 |
| 现有库结构 | `schema:check` 发现运行时表 `global_schema_migrations.queued_at` 与修复脚本定义不一致 | 必须先决定该表的基础设施例外规则 |
| 多站点冒烟测试 | 创建 Global 站点 Host 时实际返回 202，测试仍期待 201 | 需要确认审核异步响应协议并修正测试或实现 |

## Beta 发布前必须完成

以下事项未完成前，不应把 v1.0 beta 宣布为数据库结构冻结版本：

- 定稿所有表的公共字段顺序，并明确 `key`、`queued_at` 是否属于业务字段以及它们的位置。
- 统一所有外键和跨表引用的语义名称，消除仍以 `_key` 表示关系的字段；稳定的外部标识和安全令牌继续保留字符串类型。
- 去掉 `created_at`、`updated_at` 的数据库默认值，由公共数据层统一补充，并让新增和更新接口拒绝业务层传入公共审计字段。
- 对每个唯一索引标注作用域：租户内唯一索引必须以 `owner_tid` 开头并纳入 `deleted_at`；协议、令牌、外部身份等全局唯一索引必须写明不带租户前缀的理由。
- 决定通用状态字段和 PVE 状态字段是否改为语义明确的枚举或专用名称。
- 处理运行时 `global_schema_migrations` 表与 Prisma/修复脚本的边界，避免 `schema:check` 长期带着已知差异通过。
- 清理未实现模型，或在需求文档中明确它们是 beta 后的计划模型；尤其不能在没有功能实现的情况下保留误导性的 SSO 表。
- 更新旧的命名需求文档和测试规则，使文档、Schema、迁移、表格列顺序检查使用同一套规范。
- 修复并重新验证多站点冒烟测试的 201/202 响应语义。

## 结构变更执行原则

结构冻结后的每一项改动都必须按以下顺序执行：

1. 先修改对应的 `prisma/*.prisma`，不直接编辑现有迁移文件。
2. 执行 `npm run prisma:migrations -- --name=<英文简述>`，让生成器为 SQLite、MySQL、PostgreSQL 和 D1 生成同编号增量迁移，并更新 `.applied` 快照。
3. 如需保留旧列数据，按“加新列 → 四方言手写搬运迁移 → 删除旧列”的三步规则执行；手写迁移不能伪装成 Prisma 生成迁移。
4. 运行 `npm run schema:verify`、`npm run schema:check`，并在空库和现有库上分别验证。
5. 运行类型检查、Worker 构建、数据库/列顺序测试和多站点冒烟测试。
6. 在交接记录中写明改动、迁移编号、数据是否丢弃、验证结果和剩余风险，再提交代码。

## 责任边界

- 本目录记录“应该怎样收敛”的判断，不替代运行时权限和数据归属校验。
- `created_at`、`updated_at`、`deleted_at`、`created_duid`、`updated_duid`、`owner_tid`、`owner_bid`、`owner_uid` 由公共数据层管理；后台和终端用户表单只能展示，不得让业务 API 自由写入。
- 业务唯一字段仍然是唯一约束，不得重新升格为主键；每张业务表的主键统一为本表自增 `id`。
- “用户”在文档中只表示网站终端用户；给项目下达指令的人按项目约定称为“主人”。
